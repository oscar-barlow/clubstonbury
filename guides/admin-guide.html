1. Set up the family survey

Google Forms and SurveyMonkey both export responses to CSV. Build one response per child with:

  • the child's name and a parent contact field;
  • first club choice (required);
  • second and third choices (optional); and
  • an automatic submission timestamp.

Use the same club spelling in every choice question. Explain eligibility, the deadline and that submission time does not affect the on-time lottery.

Choice design: let families choose up to three clubs, but do not require all three choices. Ranking a genuine lower preference cannot reduce the chance of receiving a higher-ranked choice.

2. Export and check

After the two-week window closes, stop responses and download the form results as CSV. Keep this original file in the school's protected storage.

  • Remove duplicates and test submissions.
  • Confirm each child is eligible for every chosen club.
  • Resolve spelling variants before importing.
  • Keep an untouched copy of the original export.

Clubstonbury does not decide eligibility and cannot know whether a form answer is factually correct.

Generate a unique, random-looking ID such as kid_7f3a91c2 for every child. Paste the generated IDs as values, check for duplicates, and make a separate two-column ID-to-name lookup. Do not upload that lookup.

Data protection note: IDs that the school can reconnect to names are pseudonymous, not fully anonymous. The lookup and lottery files remain personal data in the school's hands. Store them separately, limit access and follow the school's retention policy.

4. Make the two input files

Applications: exact headings

id,timestamp,choice_1,choice_2,choice_3 kid_7f3a91c2,2026-09-01T09:30:00Z,Drama,Coding,Art kid_3d8b104e,2026-09-02T13:14:00Z,Football,Drama,

id must be unique. First choice is required; second and third are optional but must be contiguous.

Capacities: one row per club

club,capacity Drama,16 Coding,12 Art,10 Football,20

Capacity is the total number of places available and may be zero. Names must match the application choices, ignoring letter case.

5. Run the allocation

  1. Open Allocate places. Select the pseudonymous applications CSV.
  2. Read validation messages. Fix blocking errors; investigate every warning.
  3. Load capacities. Upload the capacity CSV, paste values or enter them manually.
  4. Review totals. Check child count, capacity and each club row.
  5. Set the seed. Keep the generated random seed or enter a published seed. Record it.
  6. Run the lottery. Check allocations, unallocated children and waiting lists.
  7. Download the ZIP. Its timestamped filename includes the seed. Store it securely.
Reproducibility: the same prepared applications CSV, capacities, seed and algorithm version reproduce the same result. The ZIP manifest records these details and a source-file hash.

6. Join names back in, securely

allocations.csv
id, allocated_1...
+
private lookup
id, name

Open both in the school's approved spreadsheet tool. Match each allocation ID to the lookup ID, then add the child's name locally. For Excel or Google Sheets, with the result ID in A2 and the lookup ID/name in columns A/B:

=XLOOKUP(A2, Mapping!A:A, Mapping!B:B, "Missing ID")

Check that no row says "Missing ID", that every expected child appears once, and that the joined row retains the correct opaque ID. Never upload the joined file to Clubstonbury.

7. Offers, returns and mop-up

If a place is declined, offer it to the next child on that club's original waiting list. Do not reorder the list. Once that list is exhausted, offer any remaining places to late or changed applications first come, first served.

Final administrator check

  • Eligibility checked
  • Capacities confirmed
  • IDs unique
  • Warnings reviewed
  • Seed recorded
  • Results spot-checked
  • ZIP stored securely
  • Retention date set
Responsibility: use Clubstonbury at your own risk. The school or administrator is fully responsible for input accuracy, legal compliance, checking the results and every offer made from them.
